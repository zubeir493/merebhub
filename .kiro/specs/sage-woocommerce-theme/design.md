# Design Document: Sage 11 WooCommerce Theme (MerebHub Storefront Port)

## Overview

This document describes the technical architecture for porting the MerebHub Laravel/Blade storefront into a Sage 11 (roots.io) WordPress theme backed by WooCommerce. The goal is a pixel-perfect recreation of the existing Ethiopian digital software marketplace frontend — same Tailwind CSS v4 design system, same component hierarchy, same Alpine.js interaction patterns — with WordPress and WooCommerce as the data and e-commerce layer instead of Laravel/Eloquent.

### Research Summary

**Sage 11 / Acorn v4**: Sage 11 uses Acorn v4 as its application container, which boots a stripped-down Laravel application inside WordPress. Views are compiled Blade templates via the `BladeOne`/`Illuminate\View` engine registered by Acorn. Service Providers follow standard Laravel conventions. `composer.json` pulls in `roots/acorn` and `roots/sage-dirs`.

**Vite + Tailwind CSS v4**: Sage 11 ships with a `vite.config.js` using the `@roots/sage` Vite plugin, which handles Blade dependency extraction and WordPress asset injection. Tailwind CSS v4 uses `@import 'tailwindcss'` and a single `@theme {}` block — no `tailwind.config.js` needed. Alpine.js is imported as an ES module in `app.js`.

**WooCommerce Template Overrides**: WooCommerce checks for templates in `resources/views/woocommerce/` (relative to the theme root) when the theme declares `add_theme_support('woocommerce')`. Blade templates require the `.blade.php` extension and must mirror the WooCommerce template directory structure.

**Acorn View Composers**: Composers are registered in a Service Provider via `$this->app['view']->composer('view.name', ComposerClass::class)`. The Composer's `compose(View $view)` method calls WooCommerce PHP functions (`wc_get_products()`, `WC()->cart`, etc.) and calls `$view->with([...])` to inject variables.

**WooCommerce AJAX Cart**: WooCommerce ships AJAX cart handlers at `/?wc-ajax=add_to_cart`, `/?wc-ajax=remove_from_cart`, and `/?wc-ajax=update_cart`. The theme triggers these via Alpine.js `fetch` and re-renders the cart fragment.

**Keygen on WooCommerce**: After order completion, a WooCommerce `woocommerce_order_status_completed` hook fires; the theme's action handler calls the Keygen API to create a license and stores the key as `_mh_license_key` order item meta, mirroring the existing `ProvisionOrderLicense` Laravel action.

**PHP Property-Based Testing**: WP_UnitTestCase (bundled with WordPress test scaffolding) plus a standalone property-based testing library. `eris/eris` is the idiomatic PHP PBT library (ports QuickCheck generators to PHP). It integrates with PHPUnit — and therefore with WP_UnitTestCase — via the `Eris\TestTrait`. Minimum 100 iterations per property.

### Request / Response Flow

```
Browser GET /
  → WordPress template resolution: index.php → front-page.php
  → Sage maps front-page.php → resources/views/home.blade.php
  → Acorn fires HomeComposer::compose()
      → wc_get_products([...]) for catalog, deals, featured, top-sellers
      → $view->with([...])
  → Blade renders layout/app + home template
  → Vite-compiled app.css + app.js loaded
  → Alpine.js boots, x-data components initialise
  → Page delivered

Browser POST /cart/add (WC AJAX)
  → /?wc-ajax=add_to_cart
  → WooCommerce processes, returns JSON fragment
  → Alpine.js updates cart badge count
```

#### WooCommerce Template Overrides

WooCommerce resolves templates by checking `{theme}/resources/views/woocommerce/` first (Sage convention). Only the minimum necessary templates are overridden; the rest fall back to WooCommerce defaults.

Overridden templates:

| WC Template | Sage Override | Purpose |
|---|---|---|
| `checkout/form-checkout.php` | `woocommerce/checkout/form-checkout.blade.php` | Two-column MerebHub checkout layout |
| `myaccount/my-account.php` | `woocommerce/myaccount/my-account.blade.php` | Redirect to custom account layout |
| `single-product.php` | Not overridden at WC level — handled by Sage template hierarchy | Custom single product |

WooCommerce's own cart and checkout pages use the WP pages assigned in WooCommerce → Settings → Advanced. The theme wraps them in the global `layouts/app.blade.php` layout.

#### AJAX Cart

WooCommerce AJAX cart endpoints work out-of-the-box with `add_theme_support('woocommerce')`. Alpine.js drives quantity changes and item removal:

```html
<!-- Quantity stepper (in cart.blade.php) — Alpine.js manages optimistic UI, form POST handles persistence -->
<div x-data="{ qty: {{ $item->get_quantity() }} }" class="flex items-center gap-1 rounded-xl bg-zinc-50 p-1 ring-1 ring-zinc-950/10">
    <button
        type="button"
        x-on:click="qty = Math.max(1, qty - 1); $refs.form.submit()"
        :disabled="qty <= 1"
        class="grid size-10 place-items-center rounded-lg bg-white ..."
        aria-label="Decrease quantity"
    ><x-heroicon-o-minus class="size-4" /></button>
    <span x-text="qty" class="min-w-9 text-center text-sm font-extrabold tabular-nums" aria-live="polite"></span>
    <button
        type="button"
        x-on:click="qty = Math.min(10, qty + 1); $refs.form.submit()"
        :disabled="qty >= 10"
        class="grid size-10 place-items-center rounded-lg bg-white ..."
        aria-label="Increase quantity"
    ><x-heroicon-o-plus class="size-4" /></button>
    <form x-ref="form" method="POST" action="{{ wc_get_cart_url() }}" class="hidden">
        {{ wp_nonce_field('woocommerce-cart') }}
        <input type="hidden" name="cart_item_key" value="{{ $cartItemKey }}">
        <input type="hidden" name="qty" :value="qty">
        <input type="hidden" name="update_cart" value="1">
    </form>
</div>
```

For true AJAX cart updates without page reload, the `wc_add_to_cart_response` filter can be used to return a JSON fragment. The Alpine.js component listens for the WooCommerce `added_to_cart` JS event and updates the header badge count.

#### LayoutComposer (shared, bound to `*`)

Runs on every request. Provides header counts:

```php
public function compose(View $view): void
{
    $cartCount    = WC()->cart ? WC()->cart->get_cart_contents_count() : 0;
    $wishlistCount = is_user_logged_in()
        ? (int) (new WP_Query([
            'post_type'      => 'mh_wishlist_item',
            'author'         => get_current_user_id(),
            'posts_per_page' => -1,
            'fields'         => 'ids',
          ]))->found_posts
        : 0;

    $view->with([
        'headerCartCount'     => $cartCount,
        'headerWishlistCount' => $wishlistCount,
    ]);
}
```

#### HomeComposer

```php
public function compose(View $view): void
{
    // Category strip — unique _mh_category meta values across published products
    $categories = $this->getDistinctCategories();

    // Hero image — ACF option or fallback
    // Deals bar — up to 5 products with sale_price < regular_price
    $deals = wc_get_products([
        'status'   => 'publish',
        'limit'    => 5,
        'orderby'  => 'date',
        'order'    => 'DESC',
        'on_sale'  => true,
    ]);

    // Top sellers — sorted by total_sales meta, up to 12
    $topProducts = wc_get_products([
        'status'   => 'publish',
        'limit'    => 12,
        'orderby'  => 'popularity',
    ]);

    // Featured — is_featured flag (meta _mh_featured = 1), up to 4
    $featured = wc_get_products([
        'status'   => 'publish',
        'limit'    => 4,
        'meta_key' => '_featured',
        'meta_value' => 'yes',
    ]);

    // Full catalog — all published, most popular first
    $products = wc_get_products([
        'status'  => 'publish',
        'limit'   => 24,
        'orderby' => 'popularity',
        'paginate' => true,
        'page'    => max(1, get_query_var('paged')),
    ]);

    $view->with(compact('categories', 'deals', 'topProducts', 'featured', 'products'));
}
```

```php
public function compose(View $view): void
{
    $search   = sanitize_text_field($_GET['q']        ?? '');
    $category = sanitize_text_field($_GET['category'] ?? '');
    $platform = sanitize_text_field($_GET['platform'] ?? '');
    $sort     = sanitize_text_field($_GET['sort']     ?? 'popular');
    $collection = $this->detectCollection(); // 'all'|'newarrivals'|'bestsellers'|'deals'

    $args = $this->buildWcArgs($search, $category, $platform, $sort, $collection);
    $products = wc_get_products(array_merge($args, [
        'paginate' => true,
        'page'     => max(1, get_query_var('paged')),
        'limit'    => 24,
    ]));

    $categories = $this->getDistinctCategories();
    $platforms  = $this->getDistinctPlatforms();

    $view->with(compact('products', 'categories', 'platforms', 'search', 'category', 'platform', 'sort', 'collection'));
}
```

The `buildWcArgs()` method translates the `sort` param into WooCommerce `orderby`/`order` and the `category` param into `tax_query` against `product_cat`. The `platform` filter maps to a meta query on `_mh_platforms`.

### 6. Heroicons Service Provider

Heroicons are registered as anonymous Blade components mapped to inline SVG. The `HeroiconServiceProvider` reads SVG files from a bundled `resources/heroicons/` directory (or from the `blade-heroicons` package) and registers each as a `x-heroicon-o-*` / `x-heroicon-s-*` component.

```php
// app/Providers/HeroiconServiceProvider.php
namespace App\Providers;

use Roots\Acorn\ServiceProvider;
use Illuminate\Support\Facades\Blade;

class HeroiconServiceProvider extends ServiceProvider
{
    protected string $iconPath;

    public function boot(): void
    {
        $this->iconPath = get_template_directory() . '/resources/heroicons';

        foreach (['o' => 'outline', 's' => 'solid'] as $prefix => $variant) {
            $dir = "{$this->iconPath}/{$variant}";
            if (!is_dir($dir)) {
                continue;
            }
            foreach (glob("{$dir}/*.svg") as $file) {
                $name = basename($file, '.svg'); // e.g. "shopping-cart"
                $this->registerComponent("heroicon-{$prefix}-{$name}", $file);
            }
        }
    }

    private function registerComponent(string $alias, string $svgPath): void
    {
        Blade::component($alias, function () use ($svgPath) {
            // Returns a closure-based anonymous component
            return new class($svgPath) extends \Illuminate\View\Component {
                public function __construct(private string $path) {}
                public function render(): string
                {
                    $svg = file_get_contents($this->path);
                    // Inject any extra attributes (class, aria-hidden, etc.)
                    return str_replace('<svg', '<svg {{ $attributes }}', $svg);
                }
            };
        });
    }
}
```

Usage in Blade templates is identical to the Laravel app:

```html
<x-heroicon-o-shopping-cart class="size-5" />
<x-heroicon-s-heart class="size-5 text-amber-400" />
```

### 7. Wishlist Implementation

The wishlist uses a lightweight custom post type `mh_wishlist_item` — no plugin required.

#### Custom Post Type Registration (`WishlistServiceProvider`)

```php
public function boot(): void
{
    register_post_type('mh_wishlist_item', [
        'public'       => false,
        'show_ui'      => false,
        'supports'     => ['author'],
        'rewrite'      => false,
        'query_var'    => false,
        'labels'       => ['name' => 'Wishlist Items'],
    ]);

    // REST endpoint for AJAX wishlist toggle
    add_action('rest_api_init', [$this, 'registerRestRoutes']);
}

public function registerRestRoutes(): void
{
    register_rest_route('mh/v1', '/wishlist', [
        'methods'             => 'POST',
        'callback'            => [$this, 'toggleWishlist'],
        'permission_callback' => fn() => is_user_logged_in(),
    ]);
}

public function toggleWishlist(\WP_REST_Request $request): \WP_REST_Response
{
    $productId = (int) $request->get_param('product_id');
    $userId    = get_current_user_id();

    $existing = get_posts([
        'post_type'   => 'mh_wishlist_item',
        'author'      => $userId,
        'meta_query'  => [['key' => '_mh_product_id', 'value' => $productId]],
        'fields'      => 'ids',
        'numberposts' => 1,
    ]);

    if ($existing) {
        wp_delete_post($existing[0], true);
        $wishlisted = false;
    } else {
        $postId = wp_insert_post(['post_type' => 'mh_wishlist_item', 'post_status' => 'publish', 'post_author' => $userId]);
        update_post_meta($postId, '_mh_product_id', $productId);
        $wishlisted = true;
    }

    return new \WP_REST_Response(['wishlisted' => $wishlisted], 200);
}
```

Post meta fields on `mh_wishlist_item`:
- `_mh_product_id` (int) — the WooCommerce product ID

The wishlist toggle on the product page is a standard HTML form POST (no JavaScript required for basic functionality). The Alpine.js enhancement upgrades the wishlist button to an optimistic AJAX toggle using the REST endpoint above.

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system — essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

PHP property-based tests use the `eris/eris` library (`giorgiosironi/eris`), which integrates with PHPUnit/WP_UnitTestCase via `Eris\TestTrait`. Each test runs a minimum of 100 iterations. Tests are placed in `tests/properties/`.

### Property 1: Discount Percentage Calculation

*For any* product price and compare-at price where `compare_at_price > price > 0`, the discount badge displayed in the Product Card must show exactly `round((1 - price / compare_at_price) * 100)` percent.

**Validates: Requirements 19.2**

### Property 2: Cart Subtotal Invariant

*For any* collection of cart line items where each item has a price in minor units (integer ≥ 0) and a quantity (integer 1–10), the rendered order summary subtotal must equal the arithmetic sum of `(price_minor * quantity)` for all items, divided by 100 and formatted to two decimal places in ETB.

**Validates: Requirements 8.5**

### Property 3: Quantity Stepper Boundary States

*For any* cart item with a quantity `q` in the valid range [1..10], the decrement button must be disabled if and only if `q == 1`, and the increment button must be disabled if and only if `q == 10`.

**Validates: Requirements 8.4**

### Property 4: Filter URL Round-Trip

*For any* combination of valid filter parameters (`q`: arbitrary string, `category`: string from the known category set, `platform`: string from the known platform set, `sort`: one of `popular|newest|rating|price_asc|price_desc`), when those parameters are passed as GET query vars to the store page, each corresponding form control in the rendered HTML must have a `value` attribute equal to the submitted parameter value.

**Validates: Requirements 5.9**

### Property 5: Search Result Count Accuracy

*For any* non-empty search query submitted to the search results page, the numeric count rendered in the results heading must equal the actual total number of products returned by the WooCommerce product query for that search term.

**Validates: Requirements 7.3**

### Property 6: Conditional Section Rendering

*For any* collection of WooCommerce products provided to the home page Composer:
- The deals bar section is rendered if and only if at least one product in the collection has `sale_price < regular_price`.
- The "Top selling this week" section is rendered if and only if the top-sellers collection is non-empty.

**Validates: Requirements 4.3, 4.4**

### Property 7: Order Status Badge Colour Mapping

*For any* WooCommerce order or subscription status value drawn from the set `{completed, on-hold, failed, cancelled, processing, pending, other}`, the rendered status badge CSS classes must match the defined mapping exactly:
- `completed` → `bg-emerald-50 text-emerald-700`
- `on-hold` → `bg-amber-50 text-amber-800`
- `failed` / `cancelled` → `bg-rose-50 text-rose-700`
- `processing` → `bg-sky-50 text-sky-700`
- all others → `bg-zinc-50 text-zinc-700`

**Validates: Requirements 13.2, 14.2**

### Property 8: Active Sidebar Link Invariant

*For any* account page route (one of `account.settings`, `account.wishlist`, `account.orders`, `account.subscriptions`), exactly one sidebar navigation link must have the active CSS class (`bg-teal-50 text-teal-700`) and `aria-current="page"`, and all other links must not have those classes.

**Validates: Requirements 12.3**

### Property 9: Order Lookup Round-Trip

*For any* WooCommerce order stored in the database with a billing email and a public reference, submitting that exact (email, reference) pair to the order lookup endpoint must return a response with `found: true` and the order's correct product name, status, and license key (when issued).

**Validates: Requirements 17.3**


## Error Handling

### WooCommerce / Cart Errors

- AJAX cart requests that fail (product out of stock, nonce expired, session expired) return a WooCommerce error JSON. Alpine.js intercepts the response and triggers an error toast via a custom `mh:toast` DOM event dispatched on `document`, which the toast container listens for.
- If `WC()` is null (WooCommerce not active), Composers guard with `if (!function_exists('wc_get_products')) { $view->with([...]); return; }` and render empty-state placeholders rather than crashing.

### REST Endpoint Errors

The order lookup endpoint returns structured errors:

```json
{ "found": false }                                         // no match — HTTP 200
{ "code": "invalid_email", "message": "..." }              // invalid email — HTTP 400
{ "code": "missing_param", "message": "..." }              // missing ref — HTTP 400
```

The Blade template on the order lookup page renders `.form-error` messages for `invalid_email` and `missing_param` codes and preserves submitted form values in the inputs.

### Template Fallbacks

- If a WooCommerce product object is null or invalid, `SingleProductComposer` calls `wp_redirect(home_url())` before Blade renders, preventing a broken product page.
- If a vendor user ID stored in product meta does not correspond to an active WordPress user, the vendor display falls back to the product author's `display_name` without a profile link.
- If `wc_get_product()` returns `false` for a wishlist item's product ID (product deleted), the product is silently omitted from the wishlist grid.

### Authentication Guards

Account pages (`account/*`, `account/wishlist`) check `is_user_logged_in()` at the top of their Composers and call `wp_redirect(wp_login_url(get_permalink()))` if not authenticated, mirroring the Laravel middleware `auth` behavior.

### Form Validation Errors

WordPress does not have a unified form validation layer. The theme uses a lightweight custom approach:

1. Form submissions go to a WP REST endpoint or a custom `admin-post.php` action.
2. Validation errors are returned as a `wp_redirect` back to the form page with `$_SESSION` or transient-stored error bag.
3. The Composer reads the error bag and passes it to the view as `$errors` (keyed by field name).
4. Blade renders `.form-error` messages using `@if (isset($errors[$field])) <p class="form-error">{{ $errors[$field] }}</p> @endif`.

For the account settings form, WooCommerce's built-in `woocommerce_save_account_details_errors` hook is used, which populates `wc_add_notice()`. Notices are consumed in the Composer and passed as `$flashError` / `$flashSuccess` variables.

### Heroicon Missing SVG

If an SVG file is missing from the heroicons directory, `HeroiconServiceProvider` silently skips that icon rather than throwing. Components that reference a missing icon render an empty `<span>` with the same attributes, preserving layout.

## Testing Strategy

### Approach

The theme uses a dual testing strategy: **PHP unit / property tests** for pure logic and data transformations, and **example-based integration tests** for rendering and WooCommerce hook integration.

Livewire is absent; no Livewire component tests are needed.

### Test Frameworks

- **WP_UnitTestCase** (via `wp-phpunit/wp-phpunit`) for WordPress-integrated unit tests and rendering assertions
- **eris/eris** for property-based tests (integrates with PHPUnit via `Eris\TestTrait`)
- **lucatume/wp-browser** (WPBrowser) for integration tests that need a real WooCommerce database
- Minimum **100 iterations** per property test (`->times(100)` or eris default)

### Property-Based Tests (`tests/properties/`)

Each of the nine correctness properties maps to one property test file:

| `FilterUrlRoundTripTest.php` | Property 4 — Filter URL round-trip | eris |

    public function discount_badge_shows_correct_percentage(): void

            Generator\choose(1, 999999),  // price (minor units, e.g. 100 = 1 ETB)
            Generator\choose(1, 1000000), // compare_at_price

        ->then(function (int $price, int $compare): void {
            $expected = (int) round((1 - $price / $compare) * 100);
            $actual   = compute_mh_discount_pct($price, $compare); // thin pure function in theme helpers

            $this->assertSame($expected, $actual,
                "Feature: sage-woocommerce-theme, Property 1: Discount percentage calculation"
            );
        });
    }
}
